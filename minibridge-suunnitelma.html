Suositus: missä pelimuoto valitaan

Pelimuoto kannattaa valita pöydän luonnissa. Pöydällä on yksi pysyvä ominaisuus, gameMode (bridge tai minibridge), ja odotushuoneessa on edelleen vain yksi aloituspainike, jonka teksti kertoo pelimuodon: ”Start bridge” tai ”Start minibridge”.

Valinta tehdään luontilomakkeen ”Game type” -valintaryhmällä, ei kahdella erillisellä luontipainikkeella. Lomake pysyy yhtenä, ja valinta toimii samoin kuin nykyinen paikanvalinta.

Perustelut

  1. Liittyjä tietää, mihin pöytään hän on menossa. Minibridge on tyypillisesti aloittelijoiden peli. Kun pelimuoto on pöydän ominaisuus, se voidaan näyttää pöytälistassa, paikanvalinnassa ja odotushuoneen otsikossa. Ruudunlukijan käyttäjä kuulee sen heti eikä vasta pelin alkaessa.
  2. Kuka tahansa voi nykyisin aloittaa pelin. startGame sallii aloituksen kaikille pöytään istuneille, ei vain luojalle. Kahden aloituspainikkeen mallissa se pelaaja, joka ehtii ensin painaa, päättäisi koko pöydän pelimuodon.
  3. Automaattiset jatkojaot tarvitsevat pysyvän tiedon. startNextDeal käynnistyy ajastimella endGamen jälkeen. Sen täytyy tietää pelimuoto ilman kenenkään painallusta, joten tieto kuuluu pöydälle joka tapauksessa.
  4. Pisteet kertyvät pöytäkohtaisesti. Minibridgen kumulatiivinen pistetilanne on mielekäs vain, jos pelimuoto ei vaihdu kesken istunnon.
  5. Flutter-asiakas yksinkertaistuu. Yksi kenttä pöydässä on helpompi toteuttaa kahdessa asiakkaassa kuin kaksi rinnakkaista aloitustapahtumaa.

Minibridgen säännöt tässä toteutuksessa

Minibridgessä ei ole tarjousvaihetta. Alla on ehdotetut oletukset. Nämä kannattaa lukita ennen koodausta, koska ne vaikuttavat sekä palvelimeen että ohjeteksteihin.

Minibridge-jaon kulku palvelimella

  1. Kortit jaetaan nykyisellä dealCards()-funktiolla.
  2. Palvelin laskee jokaisen käden pisteet ja määrittää pelaavan puolen, pelinviejän ja lepääjän.
  3. Jos tulos on 20–20, kaikille lähetetään miniRedeal ja uusi jako alkaa kolmen sekunnin kuluttua.
  4. Muuten kaikille lähetetään gameStarted, jossa on pisteet ja roolit, sitten jokaiselle omat kortit (yourCards) ja lopuksi lepääjän kortit (dummyRevealed).
  5. Pelinviejä lähettää chooseMiniContract. Palvelin tarkistaa lähettäjän ja sopimuksen.
  6. Palvelin täyttää biddingState-kentät ja kutsuu olemassa olevaa moveToPlayPhase()-funktiota. Siitä eteenpäin pelaaminen, tikit ja jakojen vuorottelu toimivat nykyisellä koodilla.
  7. endGame laskee minibridge-pisteet ja lisää ne pöydän kumulatiiviseen tilanteeseen.

Toteutuksen vaiheet

Vaiheet on järjestetty niin, että palvelin valmistuu ensin ja jokaisen vaiheen jälkeen tavallinen bridge toimii edelleen.

Vaihe 1: pöydän tietomalli ja pelimuoto

Lisää pöytään gameMode, miniState ja miniScore. Tuntematon tai puuttuva arvo tulkitaan bridgeksi, jolloin vanhat asiakkaat toimivat kuten ennenkin.

socket.on('createTable', ({ playerName, position, tableName, gameMode }) => {
  const mode = gameMode === 'minibridge' ? 'minibridge' : 'bridge';
  const table = {
    // ...nykyiset kentät
    gameMode: mode,
    miniState: null,
    miniScore: { ns: 0, ew: 0 }
  };

Lisää gameMode myös palautettaviin tietoihin:

  • filterTable(): gameMode: table.gameMode
  • sendActiveTables(): gameMode jokaiselle pöydälle

Valmis, kun uusi pöytä voidaan luoda kummassakin tilassa ja tableInfo kertoo tilan.

Vaihe 2: jaon aloituksen yhdistäminen

Nyt startGame ja startNextDeal luovat pelitilan ja lähettävät kortit kumpikin omalla koodillaan. Siirrä yhteinen osa yhteen funktioon, esimerkiksi beginDeal(table, eventType), joka:

  1. luo gameState- ja biddingState-oliot (minibridgessäkin, jotta playCardin tarkistukset toimivat sellaisenaan)
  2. minibridgessä kutsuu vaiheen 3 funktiota ja käsittelee 20–20-tilanteen
  3. lähettää gameStarted- tai newDealStarted-viestin, johon lisätään gameMode ja miniState
  4. lähettää omat kortit ja minibridgessä sen jälkeen dummyRevealed-viestin

Järjestys on tärkeä: dummyRevealed lähetetään vasta yourCards-viestien jälkeen, koska asiakas luo gameState.hands-olion niiden käsittelyssä.

Valmis, kun tavallinen bridge toimii refaktoroinnin jälkeen täsmälleen kuten ennen.

Vaihe 3: pisteet ja pelinviejä

const HCP = { A: 4, K: 3, Q: 2, J: 1 };

function countHcp(hand) {
  return Object.values(hand).flat()
    .reduce((sum, v) => sum + (HCP[v] || 0), 0);
}

// Myötäpäivään jakajasta alkaen
function orderFromDealer(dealer) {
  const seats = ['north', 'east', 'south', 'west'];
  const i = seats.indexOf(dealer);
  return [...seats.slice(i), ...seats.slice(0, i)];
}

function determineMiniRoles(table) {
  const h = table.gameState.hands;
  const points = {
    north: countHcp(h.north), east: countHcp(h.east),
    south: countHcp(h.south), west: countHcp(h.west)
  };
  const ns = points.north + points.south;
  const ew = points.east + points.west;
  if (ns === ew) return { points, redeal: true };

  let [a, b] = ns > ew ? ['north', 'south'] : ['east', 'west'];
  if (points[b] > points[a]) [a, b] = [b, a];
  else if (points[a] === points[b]) {
    const order = orderFromDealer(table.currentDealer);
    if (order.indexOf(b) < order.indexOf(a)) [a, b] = [b, a];
  }
  return { points, declarer: a, dummy: b, redeal: false };
}

Tallenna tulos: table.miniState = { phase: 'contract', points, declarer, dummy }. Aseta myös gameState.gamePhase = 'contract', gameState.declarer ja gameState.dummy.

Varmista lisäksi processCardPlayissa, ettei lepääjää paljasteta minibridgessä toiseen kertaan ensimmäisen kortin kohdalla. Muuten ruudunlukija voi ilmoittaa saman asian kahdesti.

Vaihe 4: sopimuksen valinta

Uusi tapahtuma chooseMiniContract. Sopimus muunnetaan nykyiseen muotoon (1S, 4H, 3N), jolloin moveToPlayPhase, determineTrickWinner ja asiakkaan formatContract toimivat muuttamattomina.

socket.on('chooseMiniContract', (data) => {
  chooseMiniContract(socket, playerId, data);
});

const GAME_LEVEL = { N: 3, S: 4, H: 4, D: 5, C: 5 };
const TRUMP = { S: 'spades', H: 'hearts', D: 'diamonds', C: 'clubs', N: null };

function chooseMiniContract(socket, playerId, { tableCode, type, strain }) {
  const table = tables.get(tableCode);
  if (!table || table.gameMode !== 'minibridge')
    return sendError(socket, 'Not a minibridge table');
  const ms = table.miniState;
  if (!ms || ms.phase !== 'contract')
    return sendError(socket, 'Contract cannot be chosen now');
  if (table.players[ms.declarer]?.id !== playerId)
    return sendError(socket, 'Only the declarer chooses the contract');
  if (!['S', 'H', 'D', 'C', 'N'].includes(strain) || !['partscore', 'game'].includes(type))
    return sendError(socket, 'Invalid contract');

  const level = type === 'game' ? GAME_LEVEL[strain] : 1;
  Object.assign(table.biddingState, {
    contract: `${level}${strain}`,
    declarer: ms.declarer,
    dummy: ms.dummy,
    trumpSuit: TRUMP[strain],
    biddingComplete: true
  });
  ms.phase = 'play';
  table.lastActivity = Date.now();
  moveToPlayPhase(table);
}

Estä samalla tarjoaminen minibridge-pöydissä makeBidin alussa: if (table.gameMode === 'minibridge') return sendError(...).

Vaihe 5: tulos ja pisteytys

Lisää scoreMiniDeal(contract, tricksMade), joka palauttaa pelinviejän puolen pisteet (negatiivinen, jos sopimus kaatuu). Kutsu sitä endGameissa, päivitä table.miniScore ja lisää gameOver-viestiin kentät dealScore ja totalScore.

function scoreMiniDeal(contract, tricksMade) {
  const level = parseInt(contract[0], 10);
  const strain = contract[1];
  const need = level + 6;
  if (tricksMade < need) return -50 * (need - tricksMade);

  const per = strain === 'C' || strain === 'D' ? 20 : 30;
  const trickPoints = (n) => strain === 'N' ? 40 + 30 * (n - 1) : per * n;
  const contractPoints = trickPoints(level);
  const overtricks = (tricksMade - need) * (strain === 'N' ? 30 : per);
  const bonus = contractPoints >= 100 ? 300 : 50;
  return contractPoints + overtricks + bonus;
}

Esimerkki: osapeli 1♠ ja 10 tikkiä antaa 170 pistettä, peli 4♠ ja 10 tikkiä 420. Juuri tämä ero opettaa minibridgessä pelin tavoittelua.

Vaihe 6: uudelleenyhdistäminen

  • Lisää gameReconnect-viestiin gameMode, miniState ja miniScore.
  • Nykyinen ehto lähettää lepääjän kortit vain, kun gamePhase === 'play'. Laajenna ehto koskemaan myös vaihetta contract.
  • Jos pelinviejä katkeaa sopimusvaiheessa, muut pelaajat odottavat. Harkitse ilmoitusta ”Waiting for declarer to reconnect”.

Vaihe 7: asiakas – pöydän luonti ja liittyminen

Lisää luontilomakkeeseen natiivi valintaryhmä ennen Create-painiketta:

<fieldset>
  <legend>Game type:</legend>
  <label><input type="radio" name="game-mode" value="bridge" checked> Bridge</label>
  <label><input type="radio" name="game-mode" value="minibridge"> Minibridge (no bidding, for beginners)</label>
</fieldset>
  • createTable() lähettää valitun arvon kentässä gameMode.
  • Paikanvalintanäkymä näyttää rivin ”Game type: Minibridge” ennen vapaita paikkoja.
  • Odotushuoneen otsikko on ”Minibridge table 1234”.
  • updateWaitingRoomPositions asettaa painikkeen tekstiksi ”Start minibridge” tai ”Start bridge”. Ilmoitus neljän pelaajan kohdalla sisältää pelimuodon.
  • Tallenna gameMode asiakkaan tilamuuttujaan tableInfo-, gameStarted- ja gameReconnect-viesteistä.

Lisää play-areaan uusi osio tarjousalueen rinnalle:

  • gameStarted- ja newDealStarted-käsittelijät: minibridgessä ohitetaan renderBiddingUI() ja kutsutaan uutta renderMiniContractUI()-funktiota.
  • Pisteluettelo: ”North 12, East 8, South 14, West 6. North-South 26.”
  • Pelinviejälle kaksi ryhmää painikkeita, joiden nimet ovat valmiiksi puhuttavia: ryhmä ”Partscore” (1 spades, 1 hearts, 1 diamonds, 1 clubs, 1 no trump) ja ryhmä ”Game” (4 spades, 4 hearts, 5 diamonds, 5 clubs, 3 no trump). Kymmenen suoraa painiketta on selkeämpi kuin kaksivaiheinen valinta.

  • canViewHandCards: salli lepääjän käden näyttäminen myös vaiheessa contract.
  • Sopimuksen jälkeen palvelin lähettää olemassa olevan biddingComplete-viestin, joten piilota käsittelijässä myös mini-contract-area.
  • Uusi käsittelijä miniRedeal: ilmoitus ”20–20. Redealing.”
  • gameOver: näytä ja ilmoita jaon pisteet sekä kokonaistilanne. Pistealueelle kokonaistilanne tikkien rinnalle.

Ilmoitusten sisältö

Jaon alussa yksi yhtenäinen ilmoitus announceToScreenReaderin kautta: ”Board 3. Points: North 12, East 8, South 14, West 6. North-South 26. South declares, North is dummy.” Pelinviejälle lisätään loppuun ”Choose the contract.” ja fokus siirretään ensimmäiseen sopimuspainikkeeseen. Muiden fokusta ei siirretä.

Vaihe 9: pikanäppäimet ja ohje

Käytä samaa kaavaa kuin tarjousvaiheessa: numero ja sen jälkeen maa. Käyttäjä ei silloin opettele mitään uutta.

  • 1 ja maa (S, H, D, C, N): osapeli
  • 3 N, 4 S/H, 5 D/C: peli
  • Muut yhdistelmät: ilmoitus ”Not a valid minibridge contract.”

Tarkista, että N ei ole jo varattu muuhun käyttöön pelinäkymässä. Lisää updateHelpContent()-listaan osio ”Game: Minibridge” sekä lyhyt sääntökuvaus, johon pääsee ohjeesta.

Vaihe 10: protokolla Flutter-asiakasta varten

Kirjaa alla oleva protokollataulukko projektin dokumentaatioon ennen Flutter-toteutusta. Koska puuttuva gameMode tulkitaan bridgeksi, Flutter-asiakas voi tukea ensin pelkkää bridgeä. Sen täytyy kuitenkin näyttää pelimuoto ja estää liittyminen minibridge-pöytään, kunnes tuki on tehty.

Testaus

  1. Tavallinen bridge-pöytä toimii kuten ennen: tarjous, pelaaminen, automaattinen seuraava jako.
  2. Minibridge-pöytä: pisteet ovat oikein ja yhteensä 40.
  3. 20–20 johtaa uuteen jakoon, ja jakaja vaihtuu.
  4. Parivaljakon tasapisteet: pelinviejäksi tulee jakajasta myötäpäivään ensimmäinen.
  5. Muu kuin pelinviejä yrittää valita sopimuksen: virhe, tila ei muutu.
  6. Tarjousviesti minibridge-pöydässä: virhe.
  7. Kaikki kymmenen sopimusta toimivat painikkeilla ja pikanäppäimillä, ja valtti on oikea.
  8. Pisteytys: osapeli ja ylitikit, peli, kaatunut sopimus, 3NT juuri tehtynä (400).
  9. Pelinviejä katkeaa sopimusvaiheessa ja palaa: lepääjä ja valintapainikkeet palautuvat.
  10. NVDA- ja JAWS-läpikäynti: jaon alun ilmoitus kuuluu kerran, lepääjää ei ilmoiteta kahdesti, fokus osuu pelinviejällä oikein.
  11. Vanha asiakas ilman gameMode-kenttää luo edelleen bridge-pöydän.

Sivuhavainnot nykyisestä koodista

  • filterTable() ei palauta pöydän nimeä, joten luonnissa annettu nimi ei näy muille. Saman muutoksen yhteydessä voi lisätä name-kentän.
  • Asiakkaalla ei ole käsittelijää allPassed-viestille, joten ruudunlukijan käyttäjä ei kuule, miksi uusi jako alkoi. Käsittelijä kannattaa tehdä samalla kuin miniRedeal.
  • startNewGame kutsuu startGameia, joka nollaa jakonumeron. Minibridgessä sen pitäisi nollata myös miniScore, tai sitten uuden pelin ei pitäisi nollata kumpaakaan.
  • startGame sallii kenen tahansa pöytään istuneen aloittaa pelin. Jos haluat, että vain luoja voi aloittaa, table.creator on jo tallessa.
